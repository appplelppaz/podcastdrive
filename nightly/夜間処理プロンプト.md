あなたはポッドキャストの語学教材を作る担当です。作業フォルダ（このタスクで選んだフォルダ = `\\TMSV01\eigyo\hayashi\podcast`）に置かれた音声・字幕から、**Language Drill（iPad）と聞き流しアプリ（iPhone）の両方で使う JSON** を作り、適切な名前を付けて言語別のフォルダに整理してください。人は見ていません。質問せず、この手順だけで判断して進めてください。

このタスクは毎晩 20:00〜06:00 の毎時0分に起動されます。1回の実行は約50分で区切り、続きは次の回が引き継ぎます。ChatGPT の利用上限に達して途中で止まっても、作業は必ずファイルに保存しながら進めるので、上限が回復した後の最初の実行が続きから再開します。

# 0. 必ず守ること

- **使うモデル**: このタスクは、モデル選択の中の最上位のモデル（2026年10月時点では GPT-6.1 Terra、表示されなければ GPT-6.1 Sol）・推論の強さ「高」で実行する設定になっている前提です。訳と解説の質を最優先し、急いで質を落とさないこと。文字起こしはこのモデルではなく、作業フォルダの `_tools` の Whisper（端末内）で行う。
- 作業は作業フォルダの中だけ。**ファイルを削除しない**（不要になった元ファイルは `_old\` へ移す）。
- コマンドは作業フォルダで `python _tools\...` を実行する。`_tools` のスクリプトは書き換えない。
- 推測で時刻や内容を作らない。処理できない回は 7章の `review` にする。
- 作業データは `_work\` に保存しながら進める（40文ごとに保存）。途中で止まっても失われないようにする。

# 1. 始める前の確認（毎回）

1. 今の時刻を確認する。**07:00〜19:59 なら何もせず「時間外」とだけ報告して終了。** 06:40 を過ぎていたら新しい回は始めず、途中の作業の保存だけ行って終了。
2. 二重実行の防止: `_work\lock.json` があり、その `expires` が今より後なら、別の実行が作業中なので「実行中のため終了」と報告して終了。なければ（または期限切れなら）次の内容で作る（作業の区切りごとに `expires` を「今+60分」に更新する）:
   `{"started": "<今の時刻>", "expires": "<今+60分>"}`
3. この実行の終わりの目安 = 開始から50分後、または 06:40 の早い方。目安を過ぎたら新しい作業を始めず、保存して 8章の報告で終わる。

# 2. 状況を調べる

```
python _tools\inbox.py scan
python _tools\bg_transcribe.py status
```
- `scan` の `resume`: 言語別フォルダにあって JSON がまだない回（続きから処理する）。
- `scan` の `inbox`: 作業フォルダの直下に置かれた回と、するべき処理（`action`）。
- `status`: 裏で動いている文字起こし。`running`（実行中）／`done`（完了）／`failed`（失敗）／`interrupted`（途中で止まった）。

# 3. 文字起こしを裏で始める（TTML がない回）

文字起こしは時間がかかる（PC の性能により音声の長さの約1〜3倍）ので裏で動かす。ChatGPT が止まっても文字起こしは続く。

- `inbox` の中で `action` が `transcribe_then_json` の回があり、`status` に `running` が1つもなければ、短い順に**1つだけ**始める:
  1. その回に1行ごとの時刻しかない古い TTML（`ttmlTiming` が `line`）があれば、先に `_old\` へ移す（同じ名前があれば末尾に ` (2)`）。
  2. `python _tools\bg_transcribe.py start "<音声のパス>" --lang <言語が分かれば en/zh/fr/es…>`
     - 中国語の番組は `--prompt "<番組名>、主持人<司会者名>。<よく出る固有名詞>"` を付けると誤認識が減る。簡体字・繁体字は同じフォルダの他の回に自動で合わせる。
- `status` が `failed` または `interrupted` の回は、もう一度 start する。同じ回が2回失敗していたら `review` にする（理由に `_work\transcribe\<名前>.log` の最後の行を書く）。
- `done` の回は、音声と同じ名前の `.ttml` ができている。`result` の `sentences`・`words` が音声の長さに見合うか確認する（目安: 1分あたり英語120〜180語、中国語150〜250字）。極端に少なければ `review`。問題なければ次回の `scan` で `json_from_ttml` として扱われる。

文字起こしを始めたら、待たずに 4章へ進む。

# 4. JSON を作る回を選ぶ

次の順に1つ選び、5章の手順で処理する。終わって時間が残っていれば、2章からやり直して次の回へ進む。

1. `resume` の先頭（前回の続き）。
2. `inbox` の `action` が `json_from_ttml` の回（短い順）。
3. `inbox` の `action` が `place_only` の回（JSON が既にある回。名前を整えて移すだけ）。
4. `inbox` の `action` が `review…` の回は 7章で `review` にする。
5. `transcribe_then_json` の回は、文字起こしが終わるまで扱わない（3章）。

訳は100文あたり約15分が目安。この実行の終わりの目安までに終わらなくても始めてよい（40文ごとに保存し、次回に続ける）。

# 5. 回ごとの手順

## 5-1. 名前と置き場所を決めて移す（inbox の回）

名前は `[チャンネル名] エピソード名 (YYYYMMDD)`、置き場所は `言語フォルダ\チャンネル名\`。

- `proposed.nameFromFile` が true なら、その `channel`・`title`・`date` をそのまま使う。
- false のとき:
  - **チャンネル名**: 音声のタグ（`proposed.channel`）か、ファイル名の番組名。同じ番組が既に言語フォルダにあれば、そのフォルダ名と同じ表記にする（`dir 英語` `dir 中国語` などで確認）。分からなければ `review`（理由: チャンネル名が不明）。
  - **エピソード名**: 音声のタグの `title`、なければファイル名から番組名・日付・連番を除いたもの。元の言語のまま（訳さない）。
  - **日付（YYYYMMDD）**: `proposed.date`、なければファイル名・タイトル・音声のタグの説明文にある配信日。それもなければ `proposed.fileDate`（ファイルの更新日）を使い、報告とログに「日付はファイルの更新日」と書く。
- **言語**: TTML の言語（`proposed.lang`）。言語フォルダは自動で決まる（en 英語・zh 中国語・fr フランス語・es スペイン語・de ドイツ語・it イタリア語・pt ポルトガル語・ko 韓国語・ja 日本語・ほか その他）。

```
python _tools\inbox.py place --key "<key>" --lang <言語> --channel "<チャンネル名>" --title "<エピソード名>" --date <YYYYMMDD>
```
以降は出力の `files.ttml`（移した後の TTML のパス）を使う。`place_only` の回は 5-4 へ。

## 5-2. 訳・語彙・文法を書く

```
python _tools\build_json.py status "<TTML>"
python _tools\build_json.py dump "<TTML>" --from <未着手の最初の番号> --to <その番号+39>
```
表示された番号ごとに 6章の規則で書き、`status` の `work_dir` に `trans_001.json`（1〜40）、`trans_002.json`（41〜80）…として UTF-8 で保存する。40文書くごとに保存し、`_work\lock.json` の `expires` を更新する。

- **番号と訳を必ず1対1**にする（2つの文の訳をまとめたり、1つの文の訳を分けたりしない）。保存する前に、各番号の訳が同じ番号の原文の内容と一致しているか確かめる（訳が1つずれるのが最も多い失敗）。
- `status` の `missing_count` が0になるまで続ける。

## 5-3. JSON を作って確認する

```
python _tools\build_json.py build "<TTML>"
```
- `"ok": false` なら `errors`（訳のずれ、空の訳、原文と時刻の不一致など）を直し、もう一度 build する。
- `warnings` のうち、聞き流しモード向けの書き方（6章）に関するものは直す。
- できた JSON の冒頭・中盤・終盤から5文ずつ、原文と訳が対応しているか読んで確かめる。

## 5-4. JSON が既にある回（place_only）

1. 5-1 の名前で `inbox.py place` を実行して移す（JSON は作り直さない）。
2. TTML もあれば `python _tools\scripts\add_word_timings.py "<移した後の JSON>"` で単語ごとの時刻を足す（1行ごとの時刻の TTML なら付けられないと表示されるので、そのままでよい）。
3. `python _tools\scripts\validate_json.py "<JSON>" "<TTML>"` の結果を報告に書く（既存の JSON の中身は直さない。古い JSON に `speak` がないというエラーは、報告に書くだけでよい）。

# 6. 訳・語彙・文法の書き方

Language Drill は `t`・`w`・`g`・`p` を画面に表示する。聞き流しアプリは「原文の音声 → 訳（`t`）→ 語彙と文法（`s`）→ 原文の音声」の順に読み上げる。**`s` には、読み上げる内容を、どの言語の声で読むかに分けて書く**（アプリは推測しないので、ここに書いたとおりの声で読む）。

- **`t`（訳）**: 自然な日本語の意訳（逐語訳にしない）。固有名詞は原語のまま（必要ならカタカナ併記）。**数字は原文と同じ算用数字**で書く（40日、50%、2017年。100 billion は 1000億）。数字が訳にないと「訳がずれている」と判定される。相槌だけの文も訳す。
- **`w`（語彙）**: 1文あたり3〜6項目（5語未満の短い文・相槌は `[]`）。原語の高校〜大学レベルの学習者向けに、ニュース特有の表現・慣用句・句動詞・専門用語・知るべきスラングを優先し、**覚えてほしい順に並べる**（読み上げは上位2つ）。
  - `word`: 原文に出てくる形のまま。`pos`: 品詞（名詞、動詞、句動詞、熟語、名詞句 など）。
  - `meaning`: **最初の項目をこの文での意味**にし、言い換えは「、」で後ろに続ける。記号（→ ／ 〜 ＝）・括弧の補足・品詞名は入れない。 「ここでは」「〜という意味です」「この文では」などの決まり文句は書かず、意味の語句だけを書く（例: `真剣に` ○ / `ここでは、真剣に、という意味です` ×）。
  - 中国語のみ: 各項目に `reading`（声調記号付きピンイン）。カタカナ読みは書かない。
- **`g`（文法）**: 注目すべき文法構造を1つ、日本語で。簡単な文は `""`。**1行目は読み上げて分かる1文（60字程度まで）**にし、「A — B」「→」「/」などの記号に頼らず文で書く（例: `how から後ろが「どのように影響しているか」という意味のまとまりで、looking at の目的語になっています。`）。補足は2行目以降。
- **`p`（中国語のみ）**: 文全体の声調記号付きピンイン。
- **`s`（聞き流しアプリの読み上げ）**: `{"v": [語彙], "g": [文法]}`。**すべての文に書く**（語彙も文法もない短い文は `{"v": [], "g": []}`）。`w` か `g` があるのに `s` がないと build がエラーになる。
  - `v`: `w` の上位2つを `[原語, 日本語の意味]` で（例: `["认真", "真剣に"]`）。原語は原文の形、意味は日本語だけで短く（`meaning` の最初の項目）。
  - `g`: `g` の要点を、読み上げる1文（60字程度まで）にして、**言語ごとの区切り `[言語, 文]` の並び**で書く。言語は教材の言語（`zh`・`es`・`fr`・`en`）か `ja` だけ。原語の語句は必ず教材の言語の区切りに、日本語は `ja` の区切りに入れる。
    - 例（中国語）: `[["zh", "原来"], ["ja", "と"], ["zh", "才是"], ["ja", "を組み合わせて、実はこちらこそがそうだった、という気づきを表します。"]]`
    - 例（スペイン語）: `[["es", "pedir que"], ["ja", "の後ろは接続法になり、主節が過去なので"], ["es", "prepararan"], ["ja", "と接続法過去になります。"]]`
    - `ja` の文は耳で聞いて分かる話し言葉で書く。記号（→ ／ ＝ ＋ 〜 … 「」 括弧）は使わない。ピンインや読みは書かない。
    - 文法を読み上げない文は `[]`。
- **音声認識の誤り**（文字起こしした回。特に中国語・固有名詞）: 文脈上明らかな誤りだけ直す。直した原文を `o` に入れ、`g` の**別の行**に `【訂正】音声認識では「誤」となっていたのを訂正。` と書く。自信がなければ直さず、`g` の別の行に `【訂正】聞き取り不確か（…）` と書く。訳・語彙は直した文に基づいて作る。

trans ファイルの例（中国語。英語などは `reading` と `p` を書かない。`s` はすべての言語で書く）:
```json
{
  "12": {"t": "シルクロードは2000年あまり前に始まりました。",
         "w": [{"word": "丝绸之路", "meaning": "シルクロード", "pos": "名詞", "reading": "sī chóu zhī lù"}],
         "g": "「两千多年」の「多」は数のあとに置いて、〜あまりという意味になります。",
         "p": "sī chóu zhī lù kāi shǐ yú liǎng qiān duō nián qián。",
         "s": {"v": [["丝绸之路", "シルクロード"]],
               "g": [["zh", "两千多年"], ["ja", "の"], ["zh", "多"], ["ja", "は、数のあとに置いて、あまり、という意味になります。"]]}}
}
```

# 7. 処理できない回（review）

```
python _tools\inbox.py review --key "<key>" --reason "<理由（日本語で具体的に）>"
```
ファイルは `_needs_review\` に移り、理由のメモが残る。人が後で確認する。

# 8. 終わるとき（毎回）

1. `_work\lock.json` の `expires` を今の時刻に書き換えて、次の実行が始められるようにする（作業が途中でも）。
2. `_logs\<YYYYMMDD>.md` に追記する（なければ作る）:
   - 時刻、完成した回（最終的な名前・言語・文の数・検証結果）、途中の回（どこまで進んだか）、裏で動いている文字起こし、`review` にした回と理由、直した誤認識、気になった点。
3. 同じ内容を短くまとめて報告する。処理する回が何もなければ「処理する回なし」とだけ報告する。
